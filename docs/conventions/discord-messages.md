# Discord messages

Editing, mentions, links, errors, tone, the look of embeds, forms. Moved verbatim from `CLAUDE.md` (P12, D5); its one-line rules point here.

## Notes

- **Editing a Discord message**: go through `edit_message_if_changed()` (`src.discord_ext.messages`) rather than calling `Message.edit()` directly. It enforces one order — diff the payload against what the message already shows, and only if something changed check whether the message sits in an archived thread and unarchive it before editing. Skipping the diff would make every periodic refresher resurrect archived threads for a no-op write. Pass `ignore_timestamp=True` on refreshers that stamp `datetime.now()` on each render, and `force=True` when the payload is known-new but undiffable. To change an embed the message already shows, edit `copy_embed(message.embeds[0])`, never `message.embeds[0]` itself: the in-place edit also changes the message's copy, the diff compares the embed with itself, and the edit is silently skipped (this froze the Spotify, poll and suggestion vote tallies).

- **Mentions**: `main.py` installs a default (`src/discord_ext/mentions.py`): a message sent without `allowed_mentions` pings users and roles, never `@everyone` / `@here` (the bot is an administrator on most servers, and much of what it posts carries text someone else wrote). A message rendered from a template a server's admins wrote passes `everyone_if_written(template)` so their `@everyone` still pings; text that also carries a third party's words passes `mentions_written_in(template)`; a member's input echoed back passes `NO_PINGS`; what the bot posts on a member's behalf (`/envoyer`) passes `mentions_member_could_send()`. Clip text you don't control to Discord's limits with `clip()` and the `MESSAGE_LIMIT` / `EMBED_*_LIMIT` constants of `src/core/text.py`.

- **Freshness markers in a refreshed embed**: render them from a *fixed* instant (`<t:…:R>` via `TimestampStyles.RelativeTime`), never from `datetime.now()` recomputed each cycle. Discord renders the relative label client-side and keeps "il y a 5 minutes" current on its own, so a fixed epoch stays accurate without an edit — whereas a recomputed one changes the payload every cycle and defeats `edit_message_if_changed()` entirely. Same trap with `interactions.ext.paginators.Paginator`: every button `custom_id` derives from a per-instance uuid, so rebuilding the paginator each refresh churns the components (and leaks a component callback per cycle, since `add_component_callback` rejects duplicate listeners). Keep one instance per persistent message and call `CustomPaginator.set_pages()`.

- **Posting an external link**: route it through `features.links` (`shorten_url` for a single URL, `shorten_text` for a rendered message) or `src.discord_ext.links` (`shorten_embed` / `shorten_embeds` for a whole embed) with the `guild_id` it is posted in, so it goes through that server's own Shlink instance (`moduleShlink`, P37; `None` for a DM). Every entry point degrades to the original URL when Shlink is off or unreachable — never let a shortener failure lose a post. Wired into RSS entries, YouTube notifications, the Embed manager, MDI, Streamlabs, and the Spotify/Confrérie recap messages. Links that have an *identity* (a guild's Spotify dashboard, an Embed-manager entry) go through `shorten_keyed(key, url, guild_id=…)` instead: the short URL's slug is derived from the slot key, so editing the configured target retargets the existing short URL (PATCH) rather than minting a second one — links already shared in Discord keep working. Use plain `shorten_url` for one-off targets (an RSS entry, a video) where every URL is its own thing. Periodically-refreshed embeds are safe to shorten: `shorten_url` reuses the memoized short URL and, on an API failure, falls back to the last one it minted (`cache_get(..., allow_stale=True)`), so a refresh renders an identical payload and `edit_message_if_changed()` still skips the edit. Deliberately *not* shortened: URLs Discord unfurls specially (`open.spotify.com` track links lose their player preview) and embed image/thumbnail URLs (Discord fetches those itself — `should_shorten()` rejects media URLs).

- **Interaction errors**: `extensions/errors.py` replaces interactions.py's default `CommandError` / `ComponentError` / `ModalError` listeners. Cooldowns, concurrency limits and failed checks get an ephemeral reply (French, English for a member whose Discord isn't in French); anything else is logged with its traceback and a short reference that the member is shown (`src/discord_ext/errors.py`). The reference is the interaction's correlation id, so it finds every line the interaction logged. Don't wrap a whole command in `try/except Exception` just to tell the member something went wrong: let it raise. A refusal says what to do next: the channel the command runs in (`🎵 /musique ajouter se lance dans #musique`), the right missing, named as Discord's French client names it (`author_can()` names the missing bits, `permission_names()` in `src/discord_ext/messages.py`), who can fix it (`module_off()`: an administrator, in the dashboard), what was not understood with an example (`📅 Je n'ai pas compris « 31/02 ». Exemple : 24/12/2026.`). `send_error(ctx, text, icon=…)`: 🔒 for a right, 📅 / ⏱️ for a date or duration, ❌ for the rest.

- Most user-facing strings are French — match existing language when editing command descriptions and embeds. Michel says *tu*, the dashboard included, in short sentences that say what to do next (`docs/VOIX.md`; `tests/test_voice.py` fails on a polite *vous*). Guild commands, groups, subcommands and options are named in French without accents, words joined by hyphens (`/lever-exclusion`, `depense-id:`; an option keeps its Python name through `argument_name="depense_id"`): `tests/test_command_names.py` fails on an English word it knows or a misshapen name. A module's commands share one base when there are many (`/tricount …`, `/musique …`). The exception is `random_`, which anyone can install, and `/ask` / `/ask-stats`, which were installable once: their names and descriptions are English, Discord's fallback for every client language, with a French localisation (`en_fr_name` / `en_fr_desc` in `src/discord_ext/locale.py`; `option_name` / `option_desc` for `slash_option`, which is annotated `str`), and `random_` and the interaction error replies answer in the member's language (`say()` / `is_french()` read `ctx.locale`). `/ask`'s answer follows the question's language; its buttons and notices are still French.

- **One look** (P6, `src/discord_ext/look.py`): every embed is `card(module, kind, …)`: the module's accent colour for information, the status colour for `success` / `warning` / `error` / `neutral`, the module's icon and dashboard label as the author line (`author=False` when the embed names someone), and a `Michel · <module>` footer that `card(footer=…)` or `sign()` extends. `LOOKS` holds each module's look, its icon and label kept equal to the schema's (`tests/test_module_registry.py`); the palette keeps 3:1 on Discord's dark and light embed backgrounds. An embed the admins design is `custom()`, a colour they chose for a card `card(accent=…)`. A persistent card may be a **Components V2** card (P22, B11): `card_v2(module, kind, title=…, blocks=[…], footer=…)`, a container in the module's colour with its name, the title, the blocks packed into as few texts as Discord allows (`v2_texts`: 4000 characters each, 30 at most) and the same footer; it is sent and edited with `flags=MessageFlags.IS_COMPONENTS_V2` and no `content` nor `embeds`, and a V2 card takes no timestamp (a refresher diffs nothing away). Its slot passes `v2=True` to `fetch_or_create_persistent_message` / `GuildMessages`: the placeholder is V2, and a stored message posted before is deleted and posted anew, since Discord can't turn a message into V2 by an edit. `edit_message_if_changed` compares V2 components without the ids Discord numbers them with, and a flag change counts. `ContainerComponent(…)` outside `look.py` fails `tests/test_look.py` like `Embed(…)`. A card already built with `card()` moves over with `embeds_to_v2(embeds, extra=…)` (P26): one container per embed, its title (a link when it has one), author line, thumbnail beside the title, description and fields as texts, image as a gallery and footer, the timestamp left out; past Discord's 40 components (*extra* counts what is sent beside, a row of buttons) each embed folds into one text. `CustomPaginator.v2 = True` renders its page that way with its buttons under it: send and edit with `paginator.payload()`, the buttons do too. The diff reads a media's CDN link back as `attachment://name`. Persistent cards on V2: the agenda, Satisfactory, Minecraft, Streamlabs, the Zevent and the XP leaderboard. `tests/test_look.py` fails on an `Embed(…)`, an `EmbedFooter(…)`, a `set_footer`, an `interactions` colour class or a raw `0x…` colour anywhere else. Replies start with `ok()` ✅, `oops()` ❌ (or 🔒, 📅…) or `ask()` ❓; `send_success` / `send_error` use them. Level-ups go where `levelUpDestination` says (where the member talked, a channel, a DM, nowhere), every `levelUpEvery` levels, always when a role is given. Michel says hello once in the system channel of a server that just invited it (`GuildJoin` while ready, `guild.me.joined_at` less than an hour old: the library replays `GuildJoin` for every server at startup); nothing is stored.

- **Forms and pickers** (P7): a member never types a list, an id or a long text into an option. Long text goes in a form (`Modal`: `/suggerer`, `/sondage`, `/concours lancer`, the staff's reason for a suggestion), whose `custom_id` carries the slash options a form can't hold (`giveaway_new:{role}:{level}:{host}`, `poll_new:{mode}:{multi}`); a choice among things is a select menu (`/rappel supprimer`, the role picker of `/menu-roles creer`). A moment a member types is read by `parse_when()` (`features/reminders/when.py`: "dans 2h", "demain 18h30", "samedi 9h"), and the option's autocomplete reads it back (`reading()`: « samedi 21 novembre à 09:00 ») while they type; a birthday's year and time zone are optional (`NO_YEAR`, `has_year()`: no age is said without it). A public `/sondage` is a native Discord poll (nothing stored, 1 h to 32 days: `native_poll_hours()`); anonymous and ranked ones keep their buttons, and their author's "✏️ Modifier" changes the options only while nobody has voted (`PollRepository.edit`, filtered on `votes: {}`). A suggestion carries the staff's ✅ / ❌ / 🛠️ buttons: anyone sees them, `is_staff()` is checked at the click, the decision is taken once (`SuggestionsRepository.decide`, filtered on the statuses it may follow: `DECISIONS_FROM`), posted in its "Discussion #12" thread and sent to its author by DM. A giveaway may require a role or an XP level, checked when a member enters. A role menu is `buttons` or `select` with an optional `max_roles` (1: a new pick replaces the old, `features/reactionroles/picks.py`); the dashboard's builder sets the same two (`style`, `max_roles`; on an edit, `0` removes the limit), and `/menu-roles creer` builds it in an ephemeral draft kept in memory 15 minutes (`DRAFTS`), checking the roles picked with the dashboard's rules (`entries_refusal()`) at each pick and again at "Publier".
