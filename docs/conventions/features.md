# Feature notes

What a few features rely on, lot by lot. Moved verbatim from `CLAUDE.md` (P12, D5); its one-line rules point here.

## Notes

- **XP seasons, `/profil` and the Gazette** (P5). A season is `seasonMonths` calendar months on the Paris clock (`features/xp/seasons.py`); its ranking is summed from `xp_events` (`XpRepository.season_ranking`), so no new counter. `SeasonsMixin._close_seasons` (daily, 00:07) records a finished season's top 10 in `xp_seasons` first (`record_season`, insert-once), then posts the podium (`NO_PINGS`) and moves the `seasonChampionRoleId` role (`grantable_role` re-checked); a season ended more than 7 days ago is never announced. `/profil` and "📊 Profil" (`extensions/profile.py`) read each module's own collection through `features/profile/` only where that module is on; the Gazette (`extensions/gazette.py`, `features/gazette/`, gathered on the bot loop by `src/discord_ext/gazette.py`, which the dashboard route `routes/gazette.py` shares) does the same for one week, names members (never mentions them), and claims its ISO week in `gazette_editions` before posting, giving the claim back when the post fails. Both declare every module they read in `MODULE_KEYS`. A mixin stub for a method another mixin provides goes under `if TYPE_CHECKING:` when that mixin comes later in the MRO: a plain stub shadows the real method (`/classement` returned `None`, `tests/test_xp_seasons.py` checks).

- **Reports to moderators** (`extensions/moderation/reports.py`, `features/moderation/reports.py`): "🚩 Signaler" on a message opens a form; every report of one message is one `reports` document (`_id` the message id, the reporters pushed by one conditional upsert, so a member reports a message once) and one card in the mod-log channel, posted or edited under the extension's `report_lock`. The bot never stores the message's text: the card quotes it. A card's buttons act with the moderator's own Discord rights (🗑️ `CAN_PURGE` in the message's channel, ⚠️ / 🔇 `MODERATE_MEMBERS` plus `can_moderate()`), and the report is claimed (`claim()`, filtered on `status: "open"`) before the action, reopened if Discord refuses it, so two moderators clicking act once. Sanctions go through `warn_member()` / `timeout_member()` (`commands.py`), shared with `/avertir`, `/exclure` and "⚠️ Avertir…"; `timeout_member()` raises `ActionRefused` only for Discord's refusal. A member reports 5 messages per 10 minutes (`ReportLimiter`, in memory); reports expire a year after the first one (TTL), a reporter is anonymised by `/mes-donnees supprimer`, the reported author's side is kept like an infraction and their export never shows who reported them.

- **First steps and the server page** (P8). The server page leads with the server: an overview (members active and messages over 7 days from `xp_events` where XP is on, the health card's problems counted, the 3 latest audit entries; `GET /api/servers/{id}/overview`, `routes/overview.py`, each part `null` rather than an error when it can't be read), then the modules as cards with a search and the filters Actifs / Disponibles / Archivés, each card saying when the dashboard last changed it (`AuditRepository.last_changes`). A module tied to an event that is over declares `__archived__ = True` on its schema (olympics, speedons): it shows under Archivés only, unless a server still has it on, and no pack enables it. A new server gets a "Pour bien démarrer" list and a wizard (`#/setup/<id>`, `src/webui/onboarding.py`, `routes/onboarding.py`): a *pack* (`PACKS`) is a preset of module settings plus the channel and role fields the wizard asks; applying it runs the module save route's own checks (`require_valid`, `require_own_channels`, `require_allowed_additions` from `routes/servers.py`), writes only the modules the server has no settings for (re-checked inside the mutator), leaves aside one missing a required field, reloads what reads them once (`reload_for_modules`) and syncs the guild. The list's steps are computed from facts (Michel's server-wide rights, modules on, the welcome channel, the moderators' role, a `template.test` of the welcome message and an `onboarding.announce` in the audit log); hiding it is the one thing stored, `servers.<id>.onboardingDismissed`. The announcement posts where the editor holds `CAN_SEND` and the bot can post with embeds (`post_announcement`).

- **Secret Santa** (`extensions/secretsanta/`, `features/secretsanta/`, the draw in `src/discord_ext/secretsanta.py`, shared with `routes/secretsanta.py`). A session is in person by default; `colis` adds the "📦 envoyé / 🎁 reçu" marks and the reminder before the exchange date (`features/secretsanta/dates.py`). A participant's own entries (wish list, gift marks) are one `secret_santa_participants` document each, keyed by member (`user_id`, an int), with a TTL 30 days after the exchange, deleted with their session. The anonymous messages are relayed by DM and never stored; their limits live in memory (`features/secretsanta/relay.py`). No custom id of a DM button names a member: a member can read the ids of the buttons they receive, so the recipient's "Répondre" names the session and the bot finds their Santa in the draw. The dashboard and `/secretsanta participants` show parcel counts, never who sent or received.

- **Community+** (P11). *Custom commands* (A9, `features/customcommands/`): an entry may take a member (`target`: `none` / `optional` / `required`, a `cible` USER option; the callback declares `cible` as a named parameter, since interactions.py passes no option to a bare `**kwargs`), fill `{auteur}`, `{cible}` (« tout le monde » when none was named) and `{serveur}` (`render.py`), show its last image link (by the path's extension) as the embed's image, wait `cooldown` seconds per member (`Cooldowns`, in memory) and be kept to `roles`; it pings what its text names plus the member aimed at, never the author. *Welcome* (A8, `extensions/welcome/`): `{pseudo}`, `{serveur}`, `{nombre}` beside `{mention}`; buttons to the rules and roles channels (`channel_url()`), "❓ Que faire ici ?" (`help_button()`, answered by the help extension: `HELP_BUTTON_ID`) and "👋 Souhaiter la bienvenue"; an arrival role (`grantable_role()` re-checked at each arrival); a DM copy with the links only. Each greeting is one conditional `$push` on the message's `welcome_greetings` document (not the newcomer, not twice, not after the 7-day TTL) and rewrites the message's last `-# 👋 …` line (`with_greetings()`), names never mentions. *Live notifications* (A10): a streamer's `twitchMentionRoleId` and `twitchNotificationTemplate` (`{streamer}`, `{titre}`, `{jeu}`, `{lien}`; `features/twitch/notify.py`), a YouTube channel's `mentionRoleId`: the role leads the post, the title can't ping, and "🔔 M'avertir" (`src/discord_ext/live_alerts.py`, custom id `twitch:alerte:<role>` / `youtube:alerte:<role>`) gives or takes the role back, refused unless it is still the configured one and `grantable_role()` allows it.

- **Round 8 Discord follow-ups** (P14). *Feur of the week*: each feur is also one `feur_events` document (`user_id`, `kind`, `at`, an 8-day TTL), personal like the counters; the Gazette names the one answered most that week who is still on the server. *Gazette intro*: `gazetteAiIntro` asks `features/gazette/intro.py` for a few lines on the weekly post only (never the preview), where the AI module is on; it spends one call under the key `gazette:<guild>` through `AiUsageRepository.reserve`, and any refusal or failure means a paper without one. *Public season*: `GET /api/public/{token}/xp/season` (404 unless seasons run, checked before the cache) gives the current season's top 10 by name. *Giveaway draws* go through `_pick_present`: the entrants are shuffled and checked one by one (still on the server, still holding the required role; Discord not answering keeps them in) until enough winners are found, rerolls too. *Welcome*: `close_greetings` (hourly) takes 👋 off the welcomes whose 7 days are over, keeping the other buttons, then marks them `closed`; the TTL deletes a greeting 2 days after it closed (`expires_grace_ttl`, which replaced `expires_ttl`). The roles link opens the oldest role menu posted in the roles channel (`first_message_in`). A module switched off is said with `module_off()` everywhere (`tests/test_refusals_say_what_to_do.py`).

- **Round 8 dashboard follow-ups** (P15). A save refused by a schema names the field by its form label and in French (`« Seuil » : doit être supérieur ou égal à 1`; `schemas._where` / `_message`: a list item is `n°2`, a map key keeps its name). A `forum` field is a channel the bot reads (the Confrérie's forums): `list_channels` marks forums `is_forum`, only a `forum` picker offers them, and `channel_ids()` checks it on save but never for the right to post. The Modération page lists the reports (`GET …/reports`, `MODERATE_MEMBERS`: they name the reporters); acting stays on the mod-log cards. `POST …/secretsanta/reveal` shows the pairs to the server's owner and administrators only (`ADMINISTRATOR`, read live; not the creator, not `MANAGE_GUILD`), audited as `secretsanta.reveal`; the card offers it when `can_reveal`. The health card adds a module's own needs where it posts (`MODULE_PERMISSIONS`: threads for suggestions, pins for the Spotify vote and the XP leaderboard). Each module card says when its own tasks last succeeded (`lastRuns` in the overview, from the extensions naming the module first in `MODULE_KEYS`).

- **Previews and the member space** (P16). "Vérifier la connexion" tries Satisfactory (`src/integrations/satisfactory.py`, the pinned client moved out of the extension: the token never goes to an unpinned server), Minecraft (`mcstatus`, as the status task), Uptime Kuma (the global settings) and YouTube (`src/integrations/youtube.py`, the key in a header); each answers 422 for missing settings and 502 without the driver's text. Each streamer's live message has the live preview and "Tester en MP" (`TESTS["moduleTwitch"]`, the input marked `data-template-text`). The Embed manager's embeds and the role-menu builder preview in the browser as `src/discord_ext/embedmanager.py` / `rolemenus.py` build them (`discordEmbed`, `discordButtons`, `discordSelect` in `js/ui/discord.js`). In "Mon espace", a repayment may be part of a line of the plan and may be one received (`direction`): never more than the line, so it only lowers a debt the plan shows; joining or leaving the Secret Santa is the buttons' conditional update, and the announcement is refreshed on the bot loop (`refresh_announcement` in `src/discord_ext/secretsanta.py`). The member space's forms count as unsaved edits (`DIRTY_SCOPE`).

- **Succès** (P18, `extensions/achievements.py`, `features/achievements/`). A badge (`BADGES`) reads what one module already stores (`qualifying_*`: starboard authors, voice ticks in `xp_events`, playlist tracks, suggestions implemented, the feur counter) or the members' `joined_at` from Discord (`seniors_of`), and is checked only where `active_badges()` says so: succès on, its `badge…` switch left on, its module on. `check_all` (hourly) awards each badge with one bulk of insert-only upserts (`award`, `"<user>:<badge>"` ids), so a badge is won once and never taken back; the first check of a badge on a server marks it in `achievements_state` and stays silent, later ones are announced in one `card()` per run (`NO_PINGS`, at most 15 lines). Nothing hooks into the modules' listeners. The badges show in `/succes`, on `/profil` (`footprint_lines`), in the member space (`member_space.badges`, section `badges`) and in the XP top members (`collect_xp_stats`, so the public page too). `achievements` is personal (`_personal_filters`), `achievements_state` isn't.

- **Agenda** (P19, `extensions/agenda.py`, `features/agenda/`, gathered on the bot loop by `src/discord_ext/agenda.py`, which `routes/agenda.py` shares). An `Entry` is a local day, a kind, a title, an optional time and link; `gather_agenda` reads each source only where its module is on (birthdays, giveaways, polls of `moduleUtils`, the Secret Santa exchange) plus Discord's scheduled events (scheduled or under way; one under way shows on today, from now), and names a source it couldn't read in `unavailable` rather than failing. Personal reminders are never read. `/agenda` answers the member alone; `refresh_all` (every 30 minutes) keeps the `agenda` slot's message in `agendaChannelId` up to date (`edit_message_if_changed`, pinned when `agendaPin`) and forgets the slot when an edit fails. The server page's calendar (`js/pages/agenda.js`) is the same days, a week per row, the days with something as a list on a phone.

- **Rattrapage** (P20, `extensions/catchup.py`, `features/ai/catchup.py`). `/rattrapage` works only in the channels of the AI module's `catchupChannelIds`, behind the same guards as `/ask`: the kill switch (`access_refusal`), a usable model (`resolve_default_model`), one call reserved for the member (`AiUsageRepository.reserve`, failing closed). It reads the last 200 messages (two pages), keeps those after the member's last one (`since_last`: never theirs, never empty ones), and spends nothing under 5. The prompt numbers them `[n]` and drops `@`; the answer's `[n]` become links to those messages (`with_links`, an unknown number goes). Ephemeral, `NO_PINGS`, nothing stored.
